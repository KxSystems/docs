# kdb+ 4.0 Release Notes

*This page details the latest features and improvements released to kdb+ 4.0.*

## 2026.07.06

### Fixes and improvements

- computing average of more than 2147483647 rows from a partitioned table returned wrong result due to overflow since 3.3

    ```q
    q)(`:T/2000.01.01/t/;`:T/2000.01.02/t/) set\: ([]1073741824#1b)
    q)\l T/
    q)select avg x from t
    raze now elides copy from both leading and trailing empty lists
    ```

- anymap like enlist"*" threw 'type even if all elements were strings, e.g.

    ```q
    q)get[`:v set ("abc";"def")]like enlist"*"
    11b
    ```

- "\n"$ was segfaulting, e.g.

    ```q
    q)"\n"$("123";"456")
    'type
    ```

- partitioned functional select was stripping the sorted attribute from step dictionaries, e.g.

    ```q
    q)`:HDB/2026.02.10/test/ set([]time:0 2 4);system"l HDB";?[test;();0b;`time`bucket!(`time;(`s#1 3!`closed`open;`time))]
    time bucket
    -----------
    0
    2    closed
    4    open
    the profiler could leave the target in a stopped state when the latter read compressed data
    ```

- x*/y with byte or short x returned wrong result since kdb+3.3, e.g.

    ```q
    q)0x01*/0x01020304
    q)1h*/1 2 3 4h
    consistently handle a&/`s#b and a|/`s#b which has been igoring seed for a nonempty array since 3.1
    q)0&/`s#1 2 3
    ```

## 2026.01.23

### New

- windows license check includes an additional check of comparing with hostname.domainname where domainname is retrieved from the DNS associated with the local computer. linux/mac already perform this check.

- this is in addition to the windows lookup of the host/domain via IP. Ref: https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getcomputernameexa (ComputerNameDnsDomain)

- license error due to host mismatch now contains extra information (domain and dns) e.g. "'license error: host testbox" can now be presented in the style "'license error: host testbox.domain host.docker.internal)"

### Fixes and improvements

- pressing Ctrl+C on Windows stopped the console from responding, since Windows 8

## 2025.12.18

- upserting a sorted column without `s# attribute to a sorted splayed column is now append when applicable

- profile could sometimes seg-fault

## 2024.07.08

### Fixes and improvements

- abnormal exits, e.g. -w abort, would be attempted from several threads at once, causing repeated output and potential crashes

    ```q
    q)a:get`:a 1:((1 2;3 4);(5 6;7 8));  (0#0;0#0)~a 0N / was: ()~a 0N
    q)update c:8,d:9 from ([]a) where i=1               / was 'length

    ```

## 2024.03.02

### New

- extended -36! (load Data-At-Rest-Encryption key) to:

    ```q
    1)Expose whether a key has already been loaded, via -36!(::), returning 0b or 1b accordingly.
    2)Lock -36! to avoid loading of another key, via -36!(`:keyfile;"password";bool), where bool indicates unlock/lock. To reload using a new key, unlock using current key and then proceed with the new key
    If load is attempted whilst locked, it throws 'DARE key locked.
    ```

### Fixes and improvements

## 2024.02.09

### Fixes and improvements

- in a partitioned select, projections used with aggregates could signal 'type, e.g.

    ```q
    q)select %[;2]sum a from t
    ```

- csv export of symbol or character vector values containing newlines "\n" are now enclosed in double quotes e.g.

    ```q
    q)csv 0:([]("foo\nbar";"baz"))
    ,"x"
    "\"foo\nbar\""
    "baz"
    file read of sym, where sym has length greater than 2097151, no longer result in parse error
    q)get `:lsym set a:`$2097153#"a"
    ```

- fill (^) with keyed tables could give inconsistent results depending on the key order, since v 3.2, e.g.

    ```q
    q)([k:1 2 3]s:110b;t:1 2 3)^([k:1 2 3]t:3 4 5)
    k| s t
    -| ---
    1| 1 3
    2| 1 4
    3| 0 5
    q)([k:1 2 3]s:110b;t:1 2 3)^reverse ([k:1 2 3]t:3 4 5)
    k| s t
    -| ---
    1| 0 3
    2| 0 4
    3| 0 5
    ```

- in a compressed hdb after .Q.MAP[], internal file descriptors were leaked to children, visible with e.g. system"ls -l /proc/self/fd"

## 2024.02.06

### NUC (Not Upwardly Compatible)

!!! note "Not backward compatible. Changes existing behavior."

- Loading shared libraries via 2: was resolving to a canonical path prior to load via the OS, since v3.6 2018.08.24; this caused issues for libs whose run-time path was relative to a sym-link. Now it resolves to an absolute path only, without resolving sym-links.

## 2023.08.11

### NUC (Not Upwardly Compatible)

- hopen on a fifo now applies access rules when used with -u 1/file, e.g.

    ```q
    q)hopen[4000]"hopen`:fifo://../somefifo" / to a server started with -u 1 -p 4000
    'access: ../somefifo
    ```

### Fixes and improvements

- in partitioned table queries, references to linked columns under group by no longer require remapping the foreign column for every group

    ```q

    ```

## 2022.10.26

### NUC (Not Upwardly Compatible)

!!! note "Not backward compatible. Changes existing behavior."

- .Q.id for atom now produces `a when contains single character that is not in .Q.an (instead of empty sym) e.g

    ```q
    q).Q.id`$"+"
    `a  (previous version returned `)
    ```

- .Q.id for atom changes are reflected in .Q.id for tables (as before, it was applied to each column name).

- .Q.id for tables also has additional logic to cater for duplicate col names (names now appended with 1,2,etc when matched against

- previous cols) after applying previously defined rules e.g.

    ```q
    q)cols .Q.id(`$("count+";"count*";"count1"))xcol([]1 2;3 4;5 6)
    `count1`count11`count12  (previous version returned `count1`count1`count1)
    q)cols .Q.id(`$("aa";"=";"+"))xcol([]1 2;3 4;5 6)
    `aa`a`a1  (previous version returned `aa`1`1)
    .Q.id now follows the same rule when provided name begins with an underscore as it does when it begins
    ```

- with a numerical character. Previously could produce an invalid column name.

    ```q
    q).Q.id`$"_"
    `a_
    q)cols .Q.id(`$("3aa";"_aa";"_aa"))xcol([]1 2;3 4;5 6)
    `a3aa`a_aa`a_aa1
    ```

### New

- l64arm build available

- m64 is now a universal binary, containing both intel and arm builds for macos.

- use lipo to extract the individual architecture binaries. e.g.

    ```q
    lipo -thin x86_64 -output q/m64/q.x64 q/m64/q
    lipo -thin arm64  -output q/m64/q.arm q/m64/q
    support for openssl v3
    ```

- on linux, q will now try to load versioned shared libraries for openssl if libssl-dev[el] is not installed.

- -p cmd line option (or \p system command) can now listen on a port within a specified range e.g.

    ```q
    q)\p 80/85
    q)\p
    81
    ```

- range of ports is inclusive & tried in a random order. A service name can be used instead of a port number. The existing

- option of using 0W to choose a free ephemeral port can be more efficient (where suitable).

- range can be used in place of port number, when setting using existing rules e.g. for hostname

    ```q
    q)\p myhost:2000/2010
    or for multithreaded port
    q)\p -2000/2010
    ```

### Fixes and improvements

- q could fail to connect to licensing servers on startup intermittently whilst running under an on-demand licence.

- the on-demand system now honours the NO_PROXY/no_proxy environment variables, with the lowercase version taking precedence.

## 2019.10.22

### NUC (Not Upwardly Compatible)

!!! note "Not backward compatible. Changes existing behavior."

- memory can be backed by a filesystem, allowing use of dax-enabled filesystems (e.g. AppDirect) as a non-persistent memory extension for kdb+.

- cmd line option -m path to use the filesystem path specified as a separate memory domain. This splits every thread's heap in to two:

    ```q
    domain 0: regular anonymous memory (active and used for all allocs by default)
    domain 1: filesystem-backed memory
    .m namespace is reserved for objects in domain 1, however names from other namespaces can reference them too, e.g. a:.m.a:1 2 3
    \d .m changes current domain to 1, causing it to be used by all further allocs. \d .anyotherns sets it back to 0
    .m.x:x ensures the entirety of .m.x is in the domain 1, performing a deep copy of x as needed (objects of types 100-103h,112h are not copied and remain in domain 0)
    lambdas defined in .m set current domain to 1 during execution. This will nest since other lambdas don't change domains:
    q)\d .myns
    q)g:{til x}
    q)\d .m
    q)w:{system"w"};f:{.myns.g x}
    q)\d .
    q)x:.m.f 1000000;.m.w` / x allocated in domain 1
    -120!x returns x's domain (currently 0 or 1), e.g 0 1~-120!'(1 2 3;.m.x:1 2 3)
    \w returns memory info for the current domain only:
    q)value each ("\\d .m";"\\w";"\\d .";"\\w")
    -w limit (M1/m2) is no longer thread-local, but domain-local; cmdline -w, \w set limit for domain 0
    mapped is a single global counter, same in every thread's \w
    ```

- wj empty result had type 0 for incoming cols. e.g.

    ```q
    q)(t,'([]a:0#0.;b:0#0.))~wj[-2 1+\:t.t;`s`t;t:([]s:0#`;t:0#0v;p:0#0.);(q:([]s:`a;t:0v+til 2;a:1.+til 2;b:1.+til 2);(max;`a);(min;`b))]
    ```

- .Q.hmb now returns a 2 item list - the http header and contents. e.g.

    ```q
    q)2~count .Q.hmb[`:http://www.google.com;`GET;()]
    ```

### New

- multicolumn table lookup now scales smoothly, avoiding catastrophic slowdown for particular distributions of data at the expense of best-case performance. e.g.

    ```q
    q)n:3000000;t:([]`g#a:n?n;b:n?`5);q0:999?t;q1:1000?t;value each "\\t:10 t?",/:("q0";"q1")
    ```

- added support for openssl 1.1.x.

- http server now supports gzip compression via "Content-Encoding: gzip" for responses to form?... style requests.

    ```q
    response payload must be > 2000 chars and client must indicate support via "Accept-Encoding: gzip" http header.
    ```

- http client now supports gzip content, and .Q.hg/hp/hmb indicate this in the request via the http header "Accept-Encoding: gzip".

- leverage s and g attr for in with nested data in the context of the first non-virtual select constraint. e.g.

    ```q
    q)t:([]asc string til 1000000);system"ts select count i from t where x in enlist \"999999\""
    ```

- added support for -11!`:fifo. e.g.

    ```q
    q)`:log set ();h:hopen`:log;do[10;h enlist(`upd;10?5)];hclose h;system"gzip log;mkfifo logfifo;gunzip -c log.gz > logfifo&";upd:0N!;-11!`:logfifo
    q)system"mkfifo logfifo;gunzip log.gz > logfifo&";-11!`:logfifo
    ```

- -u/U password file now supports sha1 password entries. Passwords must all be plain, md5, or sha1; they cannot be mixed. e.g.

    ```q

    n.b. in the example above, the trailing @ obscures the op such that it is not recognized for optimization path. e.g. max vs max@
    ```

### Fixes and improvements

- timeout could have resulted in a different error to 'stop, e.g. 's-fail.

- -u/U filename was detecting a filename with [0|1]filename as the single char 1. Also

    ```q
    - checks supplied md5/sha1 hashes are valid hex chars
    - checks usernames are unique
    - ignores empty lines
    ```

- -u/U and \u \U reloading password file can throw errors - "-u users not unique" and "-u bad md5/sha1 hash".

- cmd line processing now checks for duplicate or  mutually exclusive flags. e.g.

    ```q
    $q -U 1 -u 1 / throws '-u or -U
    ```

- block enabling timeout when in multithreaded input mode (cmd line -p -... option). e.g.

    ```q
    @[system';("p -5000";"T 5");"can't enable timeout with -port active"~]
    ```

- vector conditional result was erroneously retaining the g attr of the rhs false expr. e.g.

    ```q
    q)`~attr ?[0011b;0;`g#0 1 2 3]
    ```

- zip params as filenames!zipParams for file compression was not defaulting compound files (e.g. nested data) to use the same settings as the rootname. e.g.

    ```q
    q)(`:splay/;`a`b`!(17 2 5;17 2 9;17 2 6))set([]a:1000 0N#1000?`4;b:asc 1000?10;c:asc 1000?10);
    q)5 5 5 9 6i~(-21!/:`$":splay/",/:("a",/:("";"#";"##")),("b";"c"))`zipLevel
    ```

- unused bytes in enum files were not being zeroed out; this has no functional impact, it is relevant only when comparing files byte by byte. e.g.

    ```q
    q)0x82d9ddf5424d4998597cf9118b893eff~md5 "c"$read1`:f set`g#`sym!0 1
    ```

- block until async message received, h[], was not processing incoming sync requests. e.g.

    ```q
    q)h:hopen 5000;neg[h]".z.w(::;::)";h[] / would cause remote to block awaiting a response message
    ```

- ^C during each, eachleft, eachright on splays could lead to seg-fault.

- dot with a splay as right argument previously seg-faulted, e.g.


- amend of splay failed to propagate file errors, e.g.

    ```q
    q)@[`:t/ set ([]1 2;3 4);`x`x1;+;flip`a`b!`:asdasd/] / previously did set t/ to +[1 2];+[3 4]
    ```
