# kdb+ 2.4 Release Notes

*This page details the latest features and improvements released to kdb+ 2.4.*

## 2009.03.09

### Fixes and improvements

- q.k only, q binaries same as 2009.03.01 - rollback of "allow select x:count i by x:time mod 60 from trade where date=.." from 2009.03.01

## 2009.03.01

### Fixes and improvements

- checks if w is still valid (for .z.a .z.u)

- allow select x:count i by x:time mod 60 from trade where date=..

## 2009.02.12

### Fixes and improvements

- solaris/sparc only - seg fault on exit when running with -ve port

- race condition causing crash in slave mode (-s n)

- report error for:  select .. by table from table

- multithread function parse was sometimes setting context incorrectly

## 2009.02.02

### Fixes and improvements

- refine symbol search in parse tree, e.g. allows select size where price>avg price by sym from trade where ...

- Linux only - Floating Point Exception on startup on some linux versions

## 2009.02.01

### Fixes and improvements

- allow a non par.txt \l after a par.txt

- allow keyedtable upsert table-with-columns-out-of-order

- redo lj with .Q.fl, e.g. ([]a:2 3;b:3 4)lj([a:2 3]b:4 0N)

## 2008.12.17

### Fixes and improvements

- reinstate \`u#() and \`s#()

- propagate linux errno through close(). e.g. hopen`:foo:1234

## 2008.12.01

### Fixes and improvements

- all platforms; q.k changed only as global variable e was left defined after q.k loaded

## 2008.11.28

### Fixes and improvements

- linux only, removes glibc 2.4 dependency which crept in 2008.11.26

## 2008.11.26

- Fixes a bad multithreaded problem where a bad threadexec kicked in

    (redid: .Q.p to only execute partitions(.Q.P and .Q.D) that have data)

## 2008.11.25

### New

- QINIT - env var specifies where to find q.q which is autoloaded at end of q.k

### Fixes and improvements

- blocked \`s#() \`u#() - was causing crash

- fix for parsing times ("VV";",")0:("1,2";"3,4")

- chk params for -10!(an undocumented function now has extra param checks. Don't ask about or use.)

- redone uj(by redoing fl)]

## 2008.10.30

- {@[get;x;::]}each"()" was returning incorrect value

- {t:([]a:\`a\`b\`c;b:1 2 3);![t;();0b;enlist\`b]}[] used to crash when running remotely via a multi-threaded server

- {b:2;select a,b from ([]a:til 2)}[] used to crash when running remotely via a multi-threaded server

- block list,:dict - used to crash

- block delete from \`.q and \`.Q - used to crash

- .. where id.sym\=\`msft,.. can use links in the where clause but needed to get the linked field working in the special case of first position \`p# optimization.
