# kdb+ 2.5 Release Notes

*This page details the latest features and improvements released to kdb+ 2.5.*

## 2011.02.04

### Fixes and improvements

- potentially, in extremely obscure cases, a sym compare might have matched incorrectly. This affects finding unique rows

    ```q
    in tables where at least one column is a sym.
    ```

- 0!x was not decrementing ref count of x in the event of a type error

    ```q
    e.g.0!()
    ```

## 2011.01.20

### Fixes and improvements

- calling code in dynamically loaded libraries on linux could crash randomly, since 2.6 2009.08.20

## 2010.07.23

- hopen (or khp/khpu from c) could fail if 0 was the socket descriptor allocated.

- processing incoming aync msgs whilst awaiting a sync response was causing .z.w/.z.u to lose context

    ```q
    e.g. (hopen`::5000)"(neg .z.w)\"(neg .z.w)`\""; .z.u
    ```

## 2010.06.28

### Fixes and improvements

- allow deeper nesting of (), limit was 15, now it is 100. e.g. value raze 100#'"()"

## 2010.06.20

### Fixes and improvements

- enum compare was erroneously matching null, e.g. u:enlist\`x;select from([]b:\`s#\`u\$\`\`x) where b in \`x

## 2010.06.17

### Fixes and improvements

- appending a different nested type to a nested type was crashing; now it throws 'type

    ```q
    e.g. .[`:test/;();,;([]a:(1 2;3 4))];.[`:test/;();,;([]a:(`a`b;`c`d))];get`:test/
    ```

## 2010.05.21

### Fixes and improvements

- artificial memory limit (via command line -w) could have been exceeded under some circumstances

## 2010.05.12

### Fixes and improvements

- min on a sorted list was not ignoring nulls, e.g. min asc 0n 1

## 2010.02.26

### New

- command line option -o n (and \o n) - n now represents minutes if abs[o]>23. It continues to represent hours if abs[o]<24.

    ```q
    This is to accomodate timezone offsets that are partial hours (e.g. NSI,BSE in India)
    ```

## 2009.08.26

### Fixes and improvements

- was crashing on a:(\`int\$())!();a[\`q]:0 same problem as t:([a:0 1;b:0 1]c:0 1);@[t;\`a;\`s#]

## 2009.07.27

### Fixes and improvements

- deltas 30 32 39h was returning 0N 2 7 instead of 30 2 7

- in multithreaded mode allow updates to globals via .z.ts (linux,solaris only, windows later)

- ("SS";enlist csv)0:`:file crashed if file ended on a page boundary

- block bad cast t:([a:()] b:());`t$([] a:20 30)

- extend scalar t:([]a:enlist 1);t[`b]:1

## 2009.07.21

### Fixes and improvements

- rework of .z.t to be consistent with "t"$.z.z, without losing higher resolutions of .z.z

- also `datetime casting behavior changed from round to truncate (for > millisecond precision)

- reactivated zeroing of dictionaries, e.g.

    ```q
    ((enlist {})!enlist (enlist {})!enlist (enlist {})!enlist 1000)[`;`;`]
    ```

- hclose -1 caused crash

## 2009.07.15

### Fixes and improvements

- w64 only

- allocs greater than 2GB were causing kdb+ to lock up

## 2009.07.06

### Fixes and improvements

- w64 only

- was crashing on asc 9#.5 50000

## 2009.06.29

### Fixes and improvements

- loading a file containing a symbol vector only with an attribute, where the file had been appended to, resulted in a partial load of the data ingoring the appended data.

- e.g. \`:sym set \`u#0#\`;.Q.en[\`:.;([]a:\`a\`b)];(\`:.)\`sym

- additionally, loading of this type of file could have dropped the attribute under some boundary cases.

## 2009.06.23

### Fixes and improvements

- hsym of char vector longer than 256 chars was crashing, e.g. hsym `$263?" "

- .z.t is now consistent with "t"\$.z.z (previously \`time\$ rounded and .z.T truncated)

- nonnest fset will now delete extant f#

- (0Nd;0 1) in t was crashing when t had a foriegn key

## 2009.05.29

### Fixes and improvements

- append to keyed table where key was char vectors. t:([k1:("aa";"bb");k2:("cc";"dd")]v:1 2);t,:("xx";"yy";3)

- block serialization of locked (hidden) functions (i.e. functions generated from .q_ scripts)
