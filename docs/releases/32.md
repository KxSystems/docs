# kdb+ 3.2 Release Notes

*This page details the latest features and improvements released to kdb+ 3.2.*

## 2016.12.22

### Fixes and improvements

- select with a group by sorted time was returning badly formed result (with potential crash) if it was not the only grouped column. e.g.

    ```q
    q)([minute:`p#00:00 01:00;s:`a`b];p:3 4f)~select p:first p by time.minute,s from([]time:`s#0 1 1t;s:`a`b`b;p:3 4 5f)
    ```

- .Q.gc[] leaked 16 bytes on each invocation when slave threads are in use.

    ```q
    q).Q.gc[];0N!.Q.w[]`used;do[100;.Q.gc[]];0N!.Q.w[]`used;
    ```

- bin was not matching 0n at offset 0, since 3.2 2014.07.19. e.g.

    ```q
    q)0 1 2 3~0n 1 2 3 bin 0n 1 2 3
    ```

- Fixed width parsing using 0: and 1: were not ignoring double quotes inside symbol fields, since 3.3 2015.06.09. e.g.

    ```q
    q)(3#`hello;3#`$"wor\"ld")~("SS";6 6)0:3#enlist"hello wor\"ld"
    ```

## 2016.03.09

### Fixes and improvements

- \`g attr data could be incorrect from appending an object with a g attr to an empty \`g#(), leaking memory. e.g.

    ```q
    q)do[1000;a:`g#100000#`a`b;b:`g#();b,:a;delete a,b from`.] / leaked memory
    q)a:`g#();b:`g#99#til 3;a,:b;delete a,b from`.;3 4 5~distinct `g#99#3+til 3 / incorrect index data
    ```

- `g attr data was not updated for lists when a single element was amended, now drops g attr. e.g.

    ```q
    q)~/[distinct each(`#;::)@'2#enlist@[`g#(1 2;3 4;1 2);1;:;5 6]]
    ```

- Update from dict could crash instead of throwing mismatch. e.g.

    ```q
    q)update a:@[a;`d;:;`e]from(enlist`a)!enlist(enlist`b)!enlist`c
    ```

## 2016.02.02

### Fixes and improvements

- Saving mappable data could have stored an incorrect ref count in the header,

    ```q
    causing a memory leak later when reading, since 2016.01.27. Ref counts can be checked with
    q){$[(0xfe<>x 0)|" ">(x:read1 x)1;0b;any x$[" "=x 1;4;4+8 xbar 5+x?0x00]+til 4]}`:filename
    If this returns 1b, you should use this release to load and re-save your file.
    ```

## 2016.01.27

### Fixes and improvements

- continously throwing 'close for http posts where multiple reads were necessary and connection was closed by client before all content received.

- bin with lhs of table with `g#() could cause a crash, since 3.2. e.g.

    ```q
    q)n:1000000;([]`g#();0)bin([]n?`3;n#0)
    ```

- writing the same object to multiple files concurrently could cause a crash; e.g.

    ```q
    q){[x;y](hsym`$string y)set x}[0 1]peach til 100;
    ```

- .z.w was sometimes incorrect for slave threads inside peach, affecting access control. e.g.

    ```q
    q)hopen[5001]"{.z.w}peach 0 1"
    ```

## 2015.12.02

### Fixes and improvements

- directory listings were not sorted on windows; this could stop splayed tables loading on some filesystems.

- was crashing when sym interning space exhausted (approx. 1.4 billion), now exits with error "too many syms".

- 16 vs j was corrupting memory for j > 2 billion, since v3.0. e.g.

    ```q
    q)16 vs 9223372036854775807;.Q.gc[] / gc can help trigger a crash on a corrupted heap
    ```

- on disk sort, and -23!x could crash for compressed enums. e.g.

    ```q
    q).z.zd:17 1 0;`:x set `sym!2129916#0i;-23!get`:x;hdel`:x;1b
    ```

## 2015.09.25

### Fixes and improvements

- check length in received ipc header is not negative. Was causing wsfull, now throws 'parse.

- revert pj to fill with 0i to avoid inconsistent cast to J for I+I. e.g.

    ```q
    q)([s:`a`b]n:1 2i)pj([s:`a`b]n:3 4i)
    ```

- dangling dependencies could cause a crash. e.g.

    ```q
    q)`:a set 0#`
    q)b::c.d
    q)\l a
    q)c.d:1 / crash
    ```

- self-referencing views could crash if the view was invalidated during eval. e.g.

    ```q
    q)t::t+b:1
    ```

- Reloading of password file (via \U) could cause a crash.

- q.k - .j.k now skips {}[] in json strings. e.g.

    ```q
    q)(`a`b!(1f;"aa}aa"))~.j.k .j.j `a`b!(1;"aa}aa")
    ```

## 2015.05.27

### Fixes and improvements

- select now checks that the length of used columns in a splay are of the same length. Previously it could crash. e.g.

    ```q
    q)`:t/ set([]a:500#0;b:0);`:t/b set asc 5000#0 1i;select from `:t/ where b=max b
    ```

- x div T was crashing. Now throws 'type. e.g.

    ```q
    q)0 div ([]0 1)
    ```

## 2015.05.22

### Fixes and improvements

- kdb+ could crash after a mismatch error. e.g.

    ```q
    q)([a:`p#1 2 3]c:3 4 5),([a:`p#4 5 6]d:3 4 5)
    ```

- parsing as minutes could crash if the minutes were partial. e.g.

    ```q
    q)h:hopen`:file.txt;h(4091#"a"),",23:3";hclose h;("*U";",")0:`:file.txt
    ```

## 2015.05.18

### Fixes and improvements

- Added svar to .Q.res.

## 2015.04.07

### New

- distributed each now reverts to each if .z.pd is not defined.

### Fixes and improvements

- kdb+ could stall at 0% cpu or crash when decompressing files if very low on memory.

## 2015.03.04

### Fixes and improvements

- var dev cov cor were throwing 'rank if passed () or an atom.

    ```q
    q)(0f;0f;0n;0f;();();();())~(dev 1;var 1;cor[1;1];cov[1;1]),((dev;var)@\:()),(cov;cor).\:2#()
    ```

- update could create a keyed table of different length columns. Now throws 'length.

    ```q
    q)update b:2 3 4 from([a:2 3]b:2 3)
    ```

- select was crashing for an optimized path when the grouped column was also selected. e.g.

    ```q
    q)select a by a from([]a:`p#0 1;b:0 1)where a in 0
    ```

- select was slow for an optimized path when the column was enumerated. e.g.

    ```q
    q)a:`p#asc`sym?1000000?`5;c:value -10000?a;system"ts select count i by a from([]a;b:1000000#0x0)where a in c"
    ```

- S#/:T was behaving differently to (S#)each T if S referenced non-existent columns, throwing a 'length error. e.g.

    ```q
    q)`a`b`c#/:([]a:1 2 3;b:10 20 30)
    ```

- some binary ops on dicts were not commutative, order sensitive, or sensitive to missing keys. e.g.

    ```q
    q){(x+y)~y+x}[(`a`b`c!1 2 3);(`a`b`c!1 0 1.5)]
    q)(`a`b`c!1 2 3)*(`a`c`b!1 0 1f)
    q)(`a`b`c!1 2 3)*(`a`b!1 0f)
    ```

## 2014.07.26

### New

- Added websocket client functionality. .z.ws must be defined before opening a websocket, e.g.

    ```q
    q).z.ws:{0N!x;} / print incoming msgs to console, no echo.
    Then open a websocket, e.g.
    q)r:(`$":ws://host:port")""GET / HTTP/1.1\r\nHost: host:port\r\n\r\n"
    If successful it will return a 2 element list of (handle;http response), e.g.
    (3i;"HTTP/1.1 101 Switching Protocols\r\nConnection: Upgrade\r\nUpgrade: websocket\r\nSec-WebSocket-Accept: HSmrc0sMlYUkAGmm5OPpG2HaGWk=\r\nSec-WebSocket-Extensions: permessage-deflate\r\n\r\n")
    and from that point on will callback via .z.ws when msgs arrive. To send msgs, use neg[handle]"text" or neg[handle]byteVector.
    If the protocol upgrade from http to websocket failed, it returns the 2 element list, with the handle as 0Ni, e.g.
    (0Ni;"HTTP/1.1 400 Bad Request\r\nContent-Type: text/html; charset=UTF-8...")
    The response text is returned for debug purposes only; ideally, you need only be concerned whether the handle is valid.
    Any other error is thrown as usual, e.g.
    'www.nonexist.badcom: No route to host
    Should you need to use websockets over ssl, e.g. wss://host:port, consider stunnel, and open from kdb+ to that stunnel with ws://.
    Basic Authentication can be passed in the char vector on opening, along with any other necessary fields such as cookies etc.
    ```
