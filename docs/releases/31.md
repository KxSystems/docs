# kdb+ 3.1 Release Notes

*This page details the latest features and improvements released to kdb+ 3.1.*

## 2016.01.27

### Fixes and improvements

- continously throwing 'close for http posts where multiple reads were necessary and connection was closed by client before all content received.

- 16 vs j was corrupting memory for j > 2 billion, since v3.0. e.g.

    ```q
    q)16 vs 9223372036854775807;.Q.gc[] / gc can help trigger a crash on a corrupted heap
    ```

- on disk sort, and -23!x could crash for compressed enums. e.g.

    ```q
    q).z.zd:17 1 0;`:x set `sym!2129916#0i;-23!get`:x;hdel`:x;1b
    ```

## 2015.05.22

### Fixes and improvements

- parsing as minutes could crash if the minutes were partial. e.g.

    ```q
    q)h:hopen`:file.txt;h(4091#"a"),",23:3";hclose h;("*U";",")0:`:file.txt
    ```

## 2015.01.20

### Fixes and improvements

- select count x was incorrectly ignoring the argument to count for certain queries, since v3.1 2013.05.15. e.g.

    ```q
    q)([]enlist 0)~select count b where b>2 from ([]a:`p#`a`a`b`c;b:til 4)where a=`a
    ```

## 2015.01.12

### Fixes and improvements

- Find (and hence ops that use find) was slow for some data distributions, since 2014.12.05. e.g.

    ```q
    q)l:1000000#`$til[10]#\:.Q.a;s:10000#-2#l;system"ts s in asc l"
    ```

## 2014.12.05

### Fixes and improvements

- mapped nested find was crashing, since 2014.11.26. e.g.

    ```q
    q)`:f set enlist"ab";()?get`:f
    ```

## 2014.11.26

### Fixes and improvements

- in,bin was erroneously sensitive to sort attr with compound types. e.g.

    ```q
    q)(10b;10b)~([] a:0 1; b:`)in/:(([] a:0 0; b:`);([] a:`s#0 0; b:`))
    ```

- find could crash for ()?int vector. e.g.

    ```q
    q)()?til 99
    ```

- min/max on an empty sorted vector was returning null. e.g.

    ```q
    q)all~/'[(min;max)@/:\:(`s#0#0;0#0)]
    ```

## 2014.09.29

### Fixes and improvements

- In a multithreaded-query, file decompression on windows was contending for internal locks inefficiently.

- vector [bin|binr] matrix was erroneously executing as vector ? matrix since 3.0 2012.07.26. e.g.

    ```q
    q)(-360 124 bin(34 35;37 38))~-360 124 bin/:(34 35;37 38)
    ```

## 2014.08.22

### Fixes and improvements

- w32 only - bin search on tables when table had no `p# was erroneous. e.g.

    ```q
    q)all{0 1~([]sym:`a`b;date:.z.d)bin([]sym:`a`b;date:.z.d)}each til 10000
    ```

- (wsum)0 was being interpreted as exit 0. Now throws 'wsum.

- When trying to append to a nested mappable file written by v2.8 or prior, throw '"no append to q2 file format"

    ```q
    rather than 'type.
    ```

- q.k - .Q.l now binds data to vars as soon as it is loaded to help overcome this edge-case of enum dependencies

    ```q
    q)a:`b`a;`:db/a set a;`:db/b set ([]b:`s#`a?`a`b);delete a from `.;system"l db"
    ```

- q.k - save`:t.xls did not correctly encode <, > and & using XML entities. e.g.

    ```q
    q)t:update SymbolColumn:`$StringColumn from ([]StringColumn:("a<b";"a,b";"a>b";"a&b"));save `:t.xls
    ```

- q.k - .Q.MAP now works with segmented databases.

- x like "" would not match ` under some common scenarios. e.g.

    ```q
    q)delete s from`.;(`s?`a`)like ""
    ```


## 2013.10.30

### NUC (Not Upwardly Compatible)

!!! note "Not backward compatible. Changes existing behavior."

- distributed each (i.e. q -s -N) no longer opens connections to slave processes automatically on ports 20000+til N.

    ```q
    It now requires .z.pd to be defined as a function which returns an int vector of unique handles (must be marked as `u#).
    These handles must not be used for other msgs; peach will close them if it receives anything other than a response msg.
    e.g. q).z.pd:{n:abs system"s";$[n=count handles;handles;[hclose each handles;:handles::`u#hopen each 20000+til n]]}
         q).z.pc:{handles::`u#handles except x;}
         q)handles:`u#`int$();
    ```

## 2013.08.19

### Fixes and improvements

- the random number generator was not thread-safe. Now the behaviour is as follows

    ```q
    rng is thread local.
    \S 1234 sets the seed for the rng for the main thread only.
    the rng in a slave thread is assigned a seed based on the slave thread number.
    in multithreaded input mode, the seed is based on socket descriptor.
    instances started on ports 20000 thru 20099 (slave procs, used with e.g. q -s -4) have the main thread's default seed based on the port number.
    e.g. q)10?10
    ```

- q.k - lower/upper now work with enums too

## 2013.04.12

### New

- peach can use multiprocess via tcp. Start up N slave processes listening on ports 20000 + til N, and then master process with -s -N.

    ```q
    Scheduling is such that the mapping of input elements to slaves processes is not preallocated; the elements are distributed as each slave completes their previous element. Whatever data is required to execute each element must exist on each slave process.
    ```

### Fixes and improvements

- reworked SSE code. Unix on Intel targets currently require sse4.2 or above.

- w32 only - alloc > 4GB caused crash instead of reporting wsful.

    ```q
    e.g. q)1000000000#1
    ```

- nested sync msgs could cause the socket to be closed erroneously, the remote throwing 'rcv: Resource temporarily unavailable.

    ```q
    e.g. q)h:hopen 55557;neg[h]@/:("0N!.z.w \"0N!{0}[]\"";"0N!.z.w \"0N!{1}[]\"")
    ```

- N.B. nested sync messaging is generally to be avoided; due to the nature of having to process incoming messages to reach a response,

    ```q
    the order of response messages may be incorrect.
    ```

## 2013.04.03
