# kdb+ 3.5 Release Notes

*This page details the latest features and improvements released to kdb+ 3.5.*

## 2023.11.21

### New

- removed the 255 byte limit from hsym, e.g.

    ```q
    q)hsym`$263?" "
    ```

- path length limit is now 4095 bytes, instead of 255

- os errors are now truncated (indicated by '..') on the left to retain the more important tail, e.g.

    ```q
    q)get`$":root/",(250#"path/"),"file"
    '..path/path/<snip>/path/file. OS reports: No such file or directory
    ```

## 2023.04.17

### NUC (Not Upwardly Compatible)

!!! note "Not backward compatible. Changes existing behavior."

- added support for openssl 1.1.x

### Fixes and improvements

- on linux/mac, kdb+ could seg-fault if at least one TLS connection was present, and a new connection was assigned a socket descriptor above 1010.

## 2023.03.13

### New

- -p cmd line option (or \p system command) can now listen on a port within a specified range e.g.

    ```q
    q)\p 80/85
    q)\p
    81
    ```

- range of ports is inclusive & tried in a random order. A service name can be used instead of a port number. The existing option of using 0W to choose a free ephemeral port can be more efficient (where suitable).

- range can be used in place of port number, when setting using existing rules e.g. for hostname

    ```q
    q)\p myhost:2000/2010
    ```

    or for multithreaded port

    ```q
    q)\p -2000/2010
    ```

## 2021.12.07

### Fixes and improvements

- select with a symbol literal under simple aggregate could seg-fault, e.g.

    ```q
    q)select sum a*(`aaf=`aaf)|(`aaf=`aaf)|(`aaf=`aaf) by b from ([]a:1 2;b:3 4)
    ```

## 2021.04.26

### Fixes and improvements

- writes to compressed files did not retry when data was only partially written by the OS, leaving the file unreadable, present since v2.8

## 2021.03.25

### New

- on windows builds, tcp send and receive buffers are no longer set to fixed sizes allowing autotuning by the OS.

### Fixes and improvements

- an error response to a sync ipc request would leave the handle in a blocking mode, potentially stalling kdb+ until another message was received on that same handle.

## 2020.11.27

### Fixes and improvements

- mapped ragged splays would sometimes leak virtual memory, e.g. select from`:ragged/

## 2020.09.22

### Fixes and improvements

- http client would throw 'close if the content-length header was missing from the response, since v.35 2020.04.16.

- fills on a vector with nulls longer than 2^31 could return incorrect result

- enumerating a symbol vector with nulls longer than 2^31 could return incorrect result

- ssl ipc and https could seg-fault under on demand

## 2020.05.04

### Fixes and improvements

- after an http client request, or under on demand licensing, \p 0 could close a handle other than the listening port,

    ```q
    and hclose h could erroneously throw 'domain, since 3.5 2020.04.16.
    ```

## 2020.04.16

### Fixes and improvements

- select was leaking memory when passed a constraint of a boolean vector of an incorrect length. e.g.

    ```q
    q)select from ([]())where 100000000#0b
    ```

- kdb+ would enter an infinite loop when reading a response to an http request if the remote disconnected during the read.

- http client was case-sensitive to http header field names. For ease of processing, all field names are now automatically converted to lowercase on reception. e.g.

    ```q
    q)(`$":http://www.kx.com:80")"GET / HTTP/1.1\r\nHost: host:port\r\n\r\n"
    ```

## 2020.02.12

*(windows only)*

### Fixes and improvements

- set was erroneously testing for the presence of the cwd, and recreating it when missing, for a fully qualified windows path containing a disk designator. e.g.

    ```q
    q)`:C:/parentdir/subdir/file set 0
    ```

## 2019.11.13

### New

- .z.ph now calls .h.val instead of value, to allow users to interpose their own evaluation code. .h.val defaults to value.

### Fixes and improvements

- to reduce the number of system calls with glibc 2.25, sorting no longer makes calls to getpid() to seed the random number generator.

- grading functions, compositions and projections was erroneous. e.g.

    ```q
    q)`s#({};{}) / sometimes threw s-fail
    ```

- functional select could erroneously engage aggregation optimisations if an application was represented as a symbol list. e.g.

    ```q
    q)f:count;t:([]1 0;2 3);(0 1!1 1)~?[t;();`x;(last;`f`x1)]
    ```

- ljf was not filling from lhs for null rhs for sorted key on rhs. e.g.

    ```q
    q)([]a:0 1;b:`x`z;c:0 0N)~([]a:0 1;b:`x`y;c:2 0N)ljf([a:`s#0 1]b:``z;c:0 0N)
    ```

## 2019.08.13

### Fixes and improvements

- serving process would print "'snd. OS reports: Broken pipe" in the event a client disconnected prior to handshake completion.

- encountering 'params, 'locals, 'globals, 'limit and 'branch errors for lambdas could leak memory. e.g.

    ```q
    q)do[5;@[value;"{[a;b;c;d;e;f;g;h;i]}";::];0N!.Q.w[]`used]
    ```

## 2019.05.15

### Fixes and improvements

- block append to enum domain files which have sort attr. e.g.

    ```q
    q)(`:myenum set`s#`a`b)?`c / now throws 'no append to `s#enum domain: myenum
    ```

- (`s#chars)ss char would return an invalid object, since kdb+3.1. e.g.

    ```q
    q)1 2~(`s#"foo")ss"o"
    ```

- .z.bm was passed the compressed message when a compressed but invalid message was deserialized.

- windows only - if kdb+ was listening on the same port as the target process for hopen, and the target was not a local interface,

    ```q
    it was random whether the target would be erroneously identified as self.
    ```

## 2019.03.07

### Fixes and improvements

- vs would seg fault if rhs was an atomic enum and the domain of the enum was not available. e.g.

    ```q
    q)@[` vs;`missingenumname!0;"type"~]
    ```

- deserializer was not validating that booleans were either 0 or 1. e.g.

    ```q
    q)@[-9!;@[-8!2#1b;14;:;0x2];"badmsg"~]&@[-9!;@[-8!1b;09;:;0x2];"badmsg"~]
    ```

- group was throwing 'rank for a table of a single column of conforming dicts (a table column). e.g.

    ```q
    q)(([]a:(`a`b!1 2;`a`b!3 4))!(1#0;1#1))~group([]a:(`a`b!1 2;`a`b!3 4))
    ```

## 2019.02.19

### Fixes and improvements

- 0: was throwing type if given a delimiter of "\000". e.g.

    ```q
    q(`a`A;`b`B)~("SS";"\000")0:("a\000b";"A\000B")
    ```

- string was not treating \000 the same as other chars. e.g.

    ```q
    q){string[x]~enlist each x}"a\000b"
    ```

## 2019.01.31

### New

- remote connections using the "qcon" text protocol are now routed to .z.pq, which defaults to calling .z.pi.

    ```q
    This allows a user to handle remote qcon connections (via .z.pq) without defining special handling for console processing (via .z.pi).
    see https://code.kx.com/q/cookbook/firewalling for locking down message handlers.
    ```

### Fixes and improvements

- under some circumstances, \d was throwing random error text for an invalid namespace.

## 2018.12.06

### Fixes and improvements

- fby was throwing the value of length rather than the symbol`length on error.

- writing to files which reside on nfs might not report an i/o error.

- fix lower for char arrays longer than 2B and speedup lowering symbols. e.g.

    ```q
    q)not{x~lower x}(1+0Wi)#.Q.A
    ```

- the symbols in the value of the result of-26! might not have been interned. e.g.

    ```q
    q){x~`$string x}'[(-26!)[]]
    ```

- indexing a splay at depth was leaking memory. e.g.

    ```q
    q)`:t/ set([]0 1);get[`:t/][0 1;`x];.Q.w[]`mmap
    ```

## 2018.10.03

### Fixes and improvements

- https responses could be incomplete. e.g.



- each/eachright/eachleft could segfault when interrupted on splay or operating on malformed splays. e.g.

    ```q
    q)t:get`:notab/ set([]a:1 2 3;b:5 6 7);hdel`:notab/b;@[t,\:;enlist`a`b!3 4;{1b}]
    ```

- listening on 0.0.0.0 was not listening on any interface, other than the unix domain socket, twice. e.g.


## 2017.08.22

### Fixes and improvements

- hopen for unix domain sockets was erroneously connecting the badly formatted \`:unix://:4444 (should be \`:unix://4444) through handle 0.

- hopen without using a hostname was not setting Server_Name_Indication for tls correctly. e.g.

    ```q

    ```

- hopen with timeout was not working for tls connections (windows client only). e.g.

    ```q
    q)hopen(`:tcps://localhost:4444;2000) / if server busy, immediately threw 'hop. OS reports: A blocking operation is currently executing.
    ```

- pad was seg faulting if given 0W as input. Now throws 'limit. e.g.

- more strict parsing of ip addresses. e.g.

    ```q
    q)0Ni~"I"$"127.a.b.1"
    ```

- creating a boolean through the c-api kb(I) function was storing input as given. Now it stores 0|1.

- 0N#dict was not throwing 'type for some inputs. e.g.

    ```q

    ```

## 2017.08.04

### Fixes and improvements

- memory usage tally for used and mmap was incorrect when peach returned data which was mapped from disk, or larger than 32MB with -g 1 cmd line.

- reassigning a view during its calculation could result in a seg fault. e.g.


- rolled back change from 2017.05.30 regarding % with dict with uncommon keys. Currently the op is applied to common keys only.

## 2017.05.02

### New

- extended SSL/TLS client to support SNI - see https://en.wikipedia.org/wiki/Server_Name_Indication.

- slaves can be adjusted at runtime, if the cmd line -s arg is set. That becomes the maximum for the process lifetime. e.g.

    ```q
    q)0N!("current slave threads";system"s");system"s 4";0N!("current,max slave threads";system"s";system"s 0N"); / q -s 8
    q)system"s 0" / disable slave threads
    q)system"s 0N" / show max slave threads
    ```

### Fixes and improvements

- saving to csv could seg fault if passed a dictionary which was not a keyed table, since 3.5t 2016.09.20. e.g.

    ```q
    q)csv 0:`a`b!10b / should throw 'type
    ```

- loading shared libraries (e.g. qml) on unix platforms could cause a seg fault if the code was using _IO_stdin.

- on windows, hopen with timeout would always throw timeout if the connection was not accepted. e.g.

    ```q
    q)hopen(`::4444;5000) / if nothing listening on 4444 'timeout after 5 seconds
    ```

- check lengths of dictionary result from indexing, as different lengths can cause a seg fault later. e.g.

    ```q
    q)@[([b:0 1]a:0 1).;(::;`c);{"length"~x}]
    ```

- optimized min/max on mapped vectors with a g or p attr. e.g.

    ```q
    q)a:get`:v set b:`g#10000000?10;system each("ts min a";"ts min b")
    ```

- select avg x by y from t was incorrect for nested x since v3.4 2016.11.18. e.g

    ```q
    q)([a:`a`b]b:enlist each 4 5.)~select avg b by a from([]a:10#`a`b;b:1 cut til 10)
    ```

- hsym was returning type 0 list when passed an empty symbol list. e.g.

    ```q
    q)11 -11 11 11h~type each hsym each(0#`;`;`a`b;())
    ```
