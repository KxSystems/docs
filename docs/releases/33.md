# kdb+ 3.3 Release Notes

*This page details the latest features and improvements released to kdb+ 3.3.*

## 2017.03.13

### Fixes and improvements

- exported ee and m9 for c-api.

## 2017.03.01

### Fixes and improvements

- select ... by time.minute could crash or wsful if time was sorted and of type datetime, timestamp or timespan. e.g.

    ```q
    q)select by time.minute from([]time:`s#2#.z.p)
    ```

- ipc msg validation could crash under some rare scenarios if given a malformed msg.

- hopen port now checks that port is within 0..65535. e.g.

    ```q
    q)hopen 0N / domain error
    ```

- processing an http post with incorrect Content-length field could cause a crash. e.g.

    ```q
    q)system"\p 14999";.z.pp:{0N!x 0} / server process
    q)`:http://127.0.0.1:14999"POST / HTTP/1.0\r\nContent-length: 150\r\n\r\n",251?.Q.a / client process
    ```

- q.k - .z.ph now returns HTTP/1.1 400 Bad Request response for uncached paging request. e.g.

    ```q
    curl -i --raw "http://127.0.0.1:5000/?\[=1"
    ```

## 2016.12.23

### Fixes and improvements

- keyedTable%atom was throwing 'nyi since v3.3 2016.09.26. e.g.

    ```q
    q)([a:`a`b`c]b:0 .1 .2)~([a:`a`b`c]b:til 3)%10
    ```

## 2016.12.22

### Fixes and improvements

- select with a group by sorted time was returning badly formed result (with potential crash) if it was not the only grouped column. e.g.

    ```q
    q)([minute:`p#00:00 01:00;s:`a`b];p:3 4f)~select p:first p by time.minute,s from([]time:`s#0 1 1t;s:`a`b`b;p:3 4 5f)
    ```

- q.k - .Q.fc was returning additional empties when count[rhs]&lt;number of slave threads, since v3.3 2015.02.12. e.g.

    ```q
    q).Q.fc[0N!]til 3; / start with q -s 4
    ```

- triadic (and above) scan leaked memory when its result is empty, since v1.0. e.g.

    ```q
    q){0N!.Q.w[]`used;value x;0N!.Q.w[]`used;}"{x+y+z}\\[0 1;();()]"
    ```

## 2016.12.08

### Fixes and improvements

- .Q.gc[] leaked 16 bytes on each invocation when slave threads are in use.

    ```q
    q).Q.gc[];0N!.Q.w[]`used;do[100;.Q.gc[]];0N!.Q.w[]`used;
    ```

## 2016.09.26

### Fixes and improvements

- q.k re-released 2016.10.28 to correct map-reduce avg fn on partitioned table using missing varable `x. e.g.

    ```q
    q)select avg p by sym from t
    ```

- J div j and F%f had precision errors, since v3.3 2016.09.01. e.g.

    ```q
    q)all(enlist[30]~(1#3000000000000)div 100000000000;enlist[0f]~-30+enlist[3000000000000.]%100000000000.)
    ```

- divide on temporal types was not returning float. e.g.

    ```q
    q){(1#x;x)}[0.00010230141846745273]~{((1#x)%y;x%y)}[2016.09.21;16:35:05.917]
    ```

- .q.k the count in avg was not ignoring nulls during map/reduce for a partitioned table. e.g

    ```q
    q)t:([]1 2 0N 0N);.Q.dpft[`:hdb;;`x;`t]each .z.d-til 2;system"l hdb";
    q)(exec distinct x from select avg x by date from t)~exec x from select avg x from t
    ```

- distributed peach was causing an error for .Q.gc[]. e.g.

    ```q
    q).z.pd:`u#0#0;.Q.gc[]
    ```

- `hh$x was erroneously using mod 60 instead of 24. e.g.

    ```q
    q)(5#12i)~`hh$12:00+0D+til 5
    ```

## 2016.09.01

### Fixes and improvements

- div (and hence xbar) was incorrect for 0N of int based types, and for negative divisors. e.g.

    ```q
    q)(0Nt div 1;-2=10 div -5)
    ```

## 2016.07.19

### Fixes and improvements

- added single random permutation for 0N?x, which was either throwing 'g0, entering an infitine loop or crashing. e.g.

    ```q
    q)0N?10
    ```

- select was erroneously throwing 'type for queries on parted column, then <,>,<=,>= on time column if time column was of timestamp type. e.g.

    ```q
    q)select from([]sym:`p#`a`a`b;time:"p"$0)where sym=`a,time<=15:50:59
    ```

- extend a select optimisation to include npz types and >= <=. Conditions are column is called "time",

    ```q
    with constraint >,<,>= or <= where 'time' is of type time,datetime,timespan,timestamp and has attr `s, and the RHS of op evaluates to an atom. e.g.
    q)n:5000000;t:([] time:`s#`timespan$til n;sym:n?`3);system"t:10 select count i from t where time <= 0D00:00:00.2"
    ```

## 2016.07.11

### Fixes and improvements

- block erroneous update of keyed table leaving key columns of a different length to that of the value columns (it could crash later). e.g.

    ```q
    q)update a:til 100 from([a:til 5];b:(`a;`b`c;`d;`e;`f))
    ```

- using empty nested data types on disk could seg fault with some ops. e.g.

    ```q
    q).Q.Xf["C";`:a];`:b set get`:a
    ```

- 0w in 0w and -0w in -0w were not matching correctly. e.g.

    ```q
    q)11b~(0w in 0w;-0w in -0w)
    ```

- setting p attribute on vector of floats which contained more than one null was throwing u-fail, since 2016.05.24. e.g.

    ```q
    q)`p#0 0n 0n
    ```

- p attr info for datetime vectors could be incorrect if values within comparison tolerance, resulting in inconsistent data or a crash, since v1.0. e.g.

    ```q
    q){(~). distinct each(`p#x;x)}@"z"$-0.057692307692307709 -0.057692307692307654 / fails test
    q)group`p#"z"$-0.057692307692307709 -0.057692307692307654 / crash
    ```

- restrict assumption of time being sorted within a block to sym column with s or p attr only. e.g.

    ```q
    q)select from flip`date`time`currency!(`s#2016.04.05 2016.04.05;08:56:50.000 07:39:24.000;`GBp`GBp)where date=2016.04.05,time<07:59:00
    ```

## 2016.05.24

### Fixes and improvements

- Fixed width parsing using 0: and 1: were not ignoring double quotes inside symbol fields, since 3.3 2015.06.09. e.g.

    ```q
    q)(3#`hello;3#`$"wor\"ld")~("SS";6 6)0:3#enlist"hello wor\"ld"
    ```

- p attr info for float vectors could be incorrect if values within comparison tolerance, resulting in inconsistent data or a crash, since v1.0. e.g.

    ```q
    q){(~). distinct each(`p#x;x)}@-0.057692307692307709 -0.057692307692307654 / fails test
    q)group`p#-0.057692307692307709 -0.057692307692307654 / crash
    ```

- trying to serialize functions loaded from shared libraries could crash. e.g.

    ```q
    q)-8!(`a;f)!0 1 / where f is a function bound from a shared library
    ```

## 2016.03.14

### Fixes and improvements

- bin was not matching 0n at offset 0, since 3.2 2014.07.19. e.g.

    ```q
    q)0 1 2 3~0n 1 2 3 bin 0n 1 2 3
    ```

## 2016.03.08

### Fixes and improvements

- \`g attr data could be incorrect from appending an object with a g attr to an empty \`g#(), leaking memory. e.g.

    ```q
    q)do[1000;a:`g#100000#`a`b;b:`g#();b,:a;delete a,b from`.] / leaked memory
    q)a:`g#();b:`g#99#til 3;a,:b;delete a,b from`.;3 4 5~distinct `g#99#3+til 3 / incorrect index data
    ```

- `g attr data was not updated for lists when a single element was amended, now drops g attr. e.g.

    ```q
    q)~/[distinct each(`#;::)@'2#enlist@[`g#(1 2;3 4;1 2);1;:;5 6]]
    ```

## 2016.02.22

### Fixes and improvements

- Update from dict could crash instead of throwing mismatch. e.g.

    ```q
    q)update a:@[a;`d;:;`e]from(enlist`a)!enlist(enlist`b)!enlist`c
    ```

## 2016.02.02

### Fixes and improvements

- Saving mappable data could have stored an incorrect ref count in the header,

    ```q
    causing a memory leak later when reading, since 2016.01.27. Ref counts can be checked with
    q){$[(0xfe<>x 0)|" ">(x:read1 x)1;0b;any x$[" "=x 1;4;4+8 xbar 5+x?0x00]+til 4]}`:filename
    If this returns 1b, you should use this release to load and re-save your file.
    ```

## 2016.01.27

### Fixes and improvements

- continously throwing 'close for http posts where multiple reads were necessary and connection was closed by client before all content received.

- bin with lhs of table with `g#() could cause a crash, since 3.2. e.g.

    ```q
    q)n:1000000;([]`g#();0)bin([]n?`3;n#0)
    ```

- writing the same object to multiple files concurrently could cause a crash; e.g.

    ```q
    q){[x;y](hsym`$string y)set x}[0 1]peach til 100;
    ```

- .z.w was sometimes incorrect for slave threads inside peach, affecting access control. e.g.

    ```q
    q)hopen[5001]"{.z.w}peach 0 1"
    ```

## 2015.12.02

### New

- added ijf which fills according to rules of ij from v2.8. e.g.

    ```q
    q)([]a:1 2;b:``z;c:1 0N)~([]a:1 2;b:`x`y;c:10 20)ij([a:1 2]b:``z;c:1 0N)
    q)([]a:1 2;b:`x`z;c:1 20)~([]a:1 2;b:`x`y;c:10 20)ijf([a:1 2]b:``z;c:1 0N)
    ```

### Fixes and improvements

- directory listings were not sorted on windows; this could stop splayed tables loading on some filesystems.

- exposed jv in c-api for windows builds.

- was crashing when sym interning space exhausted (approx. 1.4 billion), now exits with error "too many syms".

- blocked avg of symbols inside select. e.g.

    ```q
    q)@[value;"select avg x by i from ([]`a`b);0b";{x~"type"}]
    ```

## 2015.08.23

- Linux only - .Q.gc[] now drops all unused pages from RSS.

- Allow ragged splays to be queried under certain conditions - no u,p or g attr, vectors only. e.g.

    ```q
    q)`:t/ set([]a:til 5;b:0);`:t/b set 0 1;select from `:t/
    ```

## 2015.02.12

### New

- Added .z.X which provides the raw, unfiltered cmd line.

- Added .Q.Xf to write empty nested files.

- Added c-api callback to allow a shared lib to get called back when \p set to non-zero value or .z.* set by user.

    ```q
    extern V setSysNotify(V*);V callback(S s){O("%s\n",s);}K f(K x){setSysNotify(callback);R 0;}
    ```

### Fixes and improvements

- some binary ops on dicts were not commutative, order sensitive, or sensitive to missing keys. e.g.

    ```q
    q){(x+y)~y+x}[(`a`b`c!1 2 3);(`a`b`c!1 0 1.5)]
    q)(`a`b`c!1 2 3)*(`a`c`b!1 0 1f)
    q)(`a`b`c!1 2 3)*(`a`b!1 0f)
    ```

- select was crashing for an optimized path when the grouped column was also selected. e.g.

    ```q
    q)select a by a from([]a:`p#0 1;b:0 1)where a in 0
    ```

- select was slow for an optimized path when the column was enumerated. e.g.

    ```q
    q)a:`p#asc`sym?1000000?`5;c:value -10000?a;system"ts select count i by a from([]a;b:1000000#0x0)where a in c"
    q)select count i by a from([]a:`p#asc `sym?10000?`3;b:10000#0x0)where a in value
    ```

- updated .Q.Cf to write v3.x format files for empty nested char vector.

- grouped column rename was incorrect for select .. by s:a from ([]a:`g#...) where a in b. e.g.

    ```q
    q)t:([]a:`a`a`b`c`d;b:til 5);f:{select count i by s:a from x where a in `a`b`c};f[update `g#a from t]~f t
    ```
