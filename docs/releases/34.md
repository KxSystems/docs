# kdb+ 3.4 Release Notes

*This page details the latest features and improvements released to kdb+ 3.4.*

## 2019.06.03

### Fixes and improvements

- .j.j was not escaping symbols as it was char vectors. e.g.

    ```q
    q)(2#enlist x)~.j.k .j.j(`$;::)@\:x:"A\\B"
    ```

- kdb+ is not yet compatible with openssl 1.1.x due to openssl breaking their binary api; kdb+ seg faulted if openssl 1.1.x was loaded.

    ```q
    Now, if openssl 1.1.x is detected, it is ignored.
    ```

## 2019.02.07

### New

- remote connections using the "qcon" text protocol are now routed to .z.pq, which defaults to calling .z.pi.

    ```q
    This allows a user to handle remote qcon connections (via .z.pq) without defining special handling for console processing (via .z.pi).
    see https://code.kx.com/q/cookbook/firewalling for locking down message handlers.
    ```

### Fixes and improvements

- avg for char vector could crash if the vector contained a null. e.g.

    ```q
    q)81.5~avg 7500000#"abc "
    ```

- hcount`:dir was reporting an unrelated error string on unix, since 3.4t 2015.09.25.

- ipc messages with an invalid header length field of <8 bytes was corrupting memory resulting in a crash. Now throws 'badMsg.

- json serializer was not generating correct json for control chars. e.g.

    ```q
    q)"\"one\\u0013\""~.j.j "one\023"
    ```

- listening on 0.0.0.0 was not listening on any interface, other than the unix domain socket, twice. e.g.

    ```q
    q)\p 0.0.0.0:5010
    ```

- flip could create a table with zero columns which could cause a crash later. Now throws 'rank. e.g.

    ```q
    q)@[flip;(0#`)!([]());"rank"~]
    ```

- on windows only, hopen with timeout could be erroneous if there was a TLS connection active.

- on windows only, if kdb+ opened or accepted >64 connections and at least one of them used TLS, it could crash.

- an error thrown from a function during multi-arg (>2 args) scan or each could leak memory. e.g.

    ```q
    q){$[x>2;'`e;x+y+z]}\[0;til 5;til 5]
    q){$[x>2;'`e;x+y+z]}'[til 5;til 5;til 5]
    ```

- kdb+ would crash when printing to console if on startup the environment variables LINES or COLUMNS was set to "".

- invalid (.e.g non-unique or partial) enum domains could cause a crash with grouped selects. e.g.

    ```q
    q)sym:`a`b;0!select by x,x1 from([]`sym!2 0N 2 0N;til 4;til 4)
    ```

## 2017.07.31

### Fixes and improvements

- reassigning a view during its calculation could result in a crash. e.g.

    ```q
    q)a::@[value;`.a;a:1 2 3]
    ```

- improved performance of pattern select ... by sym from t where sym in ... with p or g attr on sym and few rows per distinct sym. e.g.

    ```q
    q)`:t/ set([]x:`p#til 10000000;y:10000000?0xff);z:-20?get`:t/x;system"ts select max y by x from get`:t where x in z"
    ```

- socket broadcast, -25!(handles;msg) was leaking a ref count on (::) which would cause a random crash later. e.g.

    ```q
    q)-25!(handles;msg);-16!(::)
    ```

## 2017.07.19

### Fixes and improvements

- compressed messages were not length limit checked for older clients (c.o, or kdb+ prior to v3.4), causing the client to crash.

- raze of a dictionary could throw 'type error when the value of the result is a mixed list. e.g.

    ```q
    q)d:(enlist 0)!enlist 0;e:1 2!`a`b;(0 1 2!(0;`a;`b))~raze(d;d;d;e)
    ```

- was leaking memory for failed column amend, since v2.x. e.g.

    ```q
    q)t:([]1 2 3);@[t;`x;+;"a"]
    ```

- upserting to ondisk `g#() was not checking for certian errors. e.g.

    ```q
    q)`:x set`g#();.[upsert;(`:x;([]0 1));"rank"~]
    ```

## 2017.05.03

### Fixes and improvements

- loading shared libraries (e.g. qml) on unix platforms could cause a crash if the code was using _IO_stdin.

- on windows, hopen with timeout would always throw timeout if the connection was not accepted. e.g.

    ```q
    q)hopen(`::4444;5000) / if nothing listening on 4444 'timeout after 5 seconds
    ```

- select avg x by y from t was incorrect for nested x since v3.4 2016.11.18. e.g

    ```q
    q)([a:`a`b]b:enlist each 4 5.)~select avg b by a from([]a:10#`a`b;b:1 cut til 10)
    ```

- check lengths of dictionary result from indexing, as different lengths can cause a crash later. e.g.

    ```q
    q)@[([b:0 1]a:0 1).;(::;`c);{"length"~x}]
    ```

- distinct on a vector of longs with more than 2 billion uniques was causing wsfull|crash. e.g.

    ```q
    q)distinct til prd 31#2
    ```

- .z.W was not deducting sent data from a queued message.

- hopen again checks symbol is a path. Was not checking since kdb+3.4 2016.05.31.

    ```q
    q)hopen`file / throws 'type
    ```

## 2017.03.01

### Fixes and improvements

- select ... by time.minute could crash or wsful if time was sorted and of type datetime, timestamp or timespan. e.g.

    ```q
    q)select by time.minute from([]time:`s#2#.z.p)
    ```

- the json serializer .j.j now serializes (::) to "null". e.g.

    ```q
    q)"null"~.j.j(::)
    ```

- updating a file in place was leaking a ref count. e.g.

    ```q
    q)`:a set 10#0b;@[`:a;2 3;:;11b];-16!(::)
    ```

- update could leak a ref count for (::) if target type did not match. e.g.

    ```q
    q)@[value;"update raze a from([]a:enlist enlist[`a]!enlist 0)";{}];-16!(::)
    ```

- ipc msg validation could crash under some rare scenarios if given a malformed msg with incorrectly large length fields.

    ```q
    q)@[-9!;@[-8!(0#0;1#0);15+til 12;:;0x806653b07bf67d07186f53b0];{"badmsg"~x}] / was crashing
    ```

## 2017.02.11

### Fixes and improvements

- ipc msg validation could crash under some rare scenarios if given a malformed msg.

- websocket client was sensitive to the case of the response headers sec-websocket-accept and sec-websocket-extensions.

- -25!(h;::) was not flushing the internal send buffers for each handle in h.

- setting an s attr on a vector which had a g attr and no other references was leaking memory, or removing the g attr on the original. e.g.

    ```q
    q)`s#`g#til 1000 / leaked mem
    q)v:`g#`a`b;b:`s#v!1 2;`s`g~attr each(b;v) / dropped g attr
    ```

- appending a sorted vector to an empty list was changing the s attr to g on the input. e.g.

    ```q
    q)v:`s#1 2 3;b:`g#();b,:v;`s`g~attr each(v;b)
    ```

- json serializer (.j.j) did not wrap keys in quotes for some types. e.g.

    ```q
    q)(`0`1!0 2f)~.j.k .j.j 0 1!0 2
    ```

- desc sort of a char vector was relatively much (~50x) slower than asc. e.g.

    ```q
    q)a:10000000?`char$97+til 26;system each("t asc a";"t desc a")
    ```

- http get did not allow for a result with a specified content-length > 2GB. e.g.

    ```q
    q).Q.hg`$"http://data.sdss3.org/sas/dr12/sdss/spectro/redux/specObj-dr12.fits"
    ```

## 2017.01.16

### Fixes and improvements

- reduced symbol visibility in binary to avoid clashes with other dynamically loaded code.

- hopen port now checks that port is within 0..65535. e.g.

    ```q
    q)hopen 0N / domain error
    ```

- processing an http post with incorrect Content-length field could cause a crash. e.g.

    ```q
    q)system"\p 14999";.z.pp:{0N!x 0} / server process
    q)`:http://127.0.0.1:14999"POST / HTTP/1.0\r\nContent-length: 150\r\n\r\n",251?.Q.a / client process
    ```

- allow case to work with I type. e.g.

    ```q
    q)1 20 100~0 1 2i'[1 2 3;10 20 30;100]
    ```

- q.k - .z.ph now returns HTTP/1.1 400 Bad Request response for uncached paging request. e.g.

    ```q
    curl -i --raw "http://127.0.0.1:5000/?\[=1"
    ```

- updating mappable files in situ was adjusting memory usage tally incorrectly, since v3.4 2016.02.02. e.g.

    ```q
    q){a:.Q.w[]`mmap;`:file set til 10;@[`:file;2 4 6;:;10 20 30];hdel`:file;a~.Q.w[]`mmap}[]
    ```

### Fixes and improvements

## 2016.12.08

### Fixes and improvements

- select from t where x in y was slow for large x with g attr, and small y, since v3.4 2016.03.29. e.g.

    ```q
    q)t:([]`g#6000000?500000i);system"ts select from t where x in enlist 5i"
    ```

- .Q.gc[] leaked 16 bytes on each invocation when slave threads are in use.

    ```q
    q).Q.gc[];0N!.Q.w[]`used;do[100;.Q.gc[]];0N!.Q.w[]`used;
    ```

- json parser is now RFC7159 compliant, in that it allows values at root, outside of [] and {}. e.g.

    ```q
    q).j.k each ("true";"false";"null";"12";"12.3";"\"hello\"")
    ```

- json parser requires a digit after a . for a floating point number. e.g.

    ```q
    q).j.k "12." // is an error
    ```

## 2016.11.07

### Fixes and improvements

- allow "P"$ to parse date only with delimiters "./ -", same as "Z"$.

    ```q
    q)enlist[2012.12.31]~distinct raze"d"$"PZ"$\:/:@["2012 12 31";4 7;:;]@/:"./ -"
    ```

### Fixes and improvements

- upserting to a keyed table with the first column as a list with no attribute was crashing since 2016.08.22. e.g

    ```q
    q)t:([a:1#enlist"";b:1#`]c:1#0N;d:1#0N); `t upsert `a`b`c!({};`;1);
    ```

- J div j and F%f had precision errors, since v3.4 2015.11.20. e.g.

    ```q
    q)all(enlist[30]~(1#3000000000000)div 100000000000;enlist[0f]~-30+enlist[3000000000000.]%100000000000.)
    ```

- divide on temporal types was not returning float. e.g.

    ```q
    q){(1#x;x)}[0.00010230141846745273]~{((1#x)%y;x%y)}[2016.09.21;16:35:05.917]
    ```

- .q.k the count in avg was not ignoring nulls during map/reduce for a partitioned table. e.g

    ```q
    q)t:([]1 2 0N 0N);.Q.dpft[`:hdb;;`x;`t]each .z.d-til 2;system"l hdb";
    q)(exec distinct x from select avg x by date from t)~exec x from select avg x from t
    ```

- q.k - .Q.bv did not accept totally empty dirs. e.g.

    ```q
    q)`:dbx/par/par.txt 0:("../0";"../1");`:dbx/0/2016.01.01/t/ set([]0 1);
    q)`:dbx/1/2016.01.02/z set 0;hdel`:dbx/1/2016.01.02/z;system"l dbx/par";.Q.bv[]
    ```

- parsing key value pairs with 0: now allows J in addition to I+S. In 3.x I is an alias for J in this construct. e.g.

    ```q
    q){x~y}.("IJ",\:"=|")0:\:"1=a|2=b"
    ```

- distributed peach was causing an error for .Q.gc[]. e.g.

    ```q
    q).z.pd:`u#0#0;.Q.gc[]
    ```

- `hh$x was erroneously using mod 60 instead of 24. e.g.

    ```q
    q)(5#12i)~`hh$12:00+0D+til 5
    ```

## 2016.05.26

### New

- improved performance by \~10x for varchar\~\\:x and x\~/:varchar given x as list of char vectors (on disk or in-mem).

    ```q
    This is ~2x faster than like. e.g.
    q)m:1000 12#"asdf";v:"asd";n:100000;system each("t:n m~\\:v";"t:n v~/:m";"t:n m like v")
    ```

- Added .Q.hp, for http POST. e.g.

    ```q
    q).Q.hp[`:http://url;"mime/type"]"payload"
    ```

- .Q.hg can use http proxies (https with proxies is nyi).

### Fixes and improvements

- uri prefix for unix domain sockets, fifos and tls connections has changed to \`:unix://port, \`:fifo://filename and \`:tcps://host:port.

    ```q
    Allows single-shot sync requests a la `:unix://port "2+2"
    ```

- select with a group by sorted time was returning badly formed result (with potential crash) if it was not the only grouped column. e.g.

    ```q
    q)([minute:`p#00:00 01:00;s:`a`b];p:3 4f)~select p:first p by time.minute,s from([]time:`s#0 1 1t;s:`a`b`b;p:3 4 5f)
    ```

    ```q

    ```
