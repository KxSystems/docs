# kdb+ 2.7 Release Notes

*This page details the latest features and improvements released to kdb+ 2.7.*

## 2026.07.06

### New

- compression can be turned on or off for a given handle using .Q.ipc with 2 parameters of a handle and a dictionary. this enables or disables ipc compression for outgoing data.

- the dictionary uses a key of symbol z for compression, with a boolean value to turn compression on or off e.g. .Q.ipc[h;([z:0b])] switches off compression for handle 'h'.

- the standard compression rules still apply when compression enabled i.e. data should be >2000bytes and compress to less than half the size in order to be compressed

### Fixes and improvements

- since kdb+4.1 2021.03.30, in distributed (negative -s) peach mode, select, meta, update, etc erroneously used secondary processes to load columns of splayed/partitioned tables

- anymap like enlist"*" threw 'type even if all elements were strings, e.g.

    ```q
    q)get[`:v set ("abc";"def")]like enlist"*"
    11b
    ```

- "\n"$ was segfaulting, e.g.

    ```q
    q)"\n"$("123";"456")
    'type
    ```

- partitioned functional select was stripping the sorted attribute from step dictionaries, e.g.

    ```q
    q)`:HDB/2026.02.10/test/ set([]time:0 2 4);system"l HDB";?[test;();0b;`time`bucket!(`time;(`s#1 3!`closed`open;`time))]
    time bucket
    -----------
    0
    2    closed
    4    open
    the profiler could leave the target in a stopped state when the latter read compressed data
    ```

- match could seg-fault on anymap & pre-3.6 mapped nested data, e.g.

    ```q
    q)(a;b):get`:foo set (1;0x0000)
    ```

## 2026.04.01

### New

- Additional optional env variables for TLS connections (OpenSSL 1.1.0 and above required) :

- KX_SSL_MINPROTOCOL sets the minimum supported protocol values are "SSLv3", "TLSv1", "TLSv1.1", "TLSv1.2", "TLSv1.3" and "None" for no limit (default "TLSv1")

- KX_SSL_MAXPROTOCOL sets the maximum supported protocol values are "SSLv3", "TLSv1", "TLSv1.1", "TLSv1.2", "TLSv1.3" and "None" for no limit

- KX_SSL_CIPHERSUITES sets the available ciphersuites for TLSv1.3 to value. This is a colon-separated list of TLSv1.3 ciphersuite names in order of preference. This list will be combined any configured TLSv1.2 (KX_SSL_CIPHER_LIST) For available ciphers on your system run 'openssl ciphers -s -tls1_3'

### Fixes and improvements

- Since 2025.11.25, .Q.bv when run on segmented table with a table missing from the same partition across segments would result in reduced memory. A side-effect was that it could increase runtime. Now altered to reduce runtime.

- On Windows, error 'OS reports: Access is denied.' could occur when running with mutiple threads and memory mapping multiple compressed files of different sizes e.g. querying data across a partition

## 2026.01.23

### New

- license error due to host mismatch now contains extra information (domain and dns) e.g. "'license error: host testbox" can now be presented in the style "'license error: host testbox.domain host.docker.internal)"

## 2025.11.25

### NUC (Not Upwardly Compatible)

!!! note "Not backward compatible. Changes existing behavior."

- user defined c code called from kdb+ (112 type) no longer called with altered subnormal registry flags that may have been changed from system default

- assignment to if/do/while now blocked at parse time. previously could lead to seg-fault

    ```q
    q){ if[a;1 2]:3 4 }
    'assign
    q)do:1
    'assign
    ```

### New

- new alternative value for environment variable KX_SSL_VERIFY_SERVER is HOSTIP. Additional validation is used when a TLS/SSL connection is being

- opened from a client. OpenSSL 1.0.2 and above is required.

- When a hostname is used to connect via TLS/SSL, it checks if the server certificate Subject Alternative Name (SAN) or Subject CommonName (CN) matches the specified hostname (ref:X509_check_host).

- When an IP is used to connect via TLS/SSL, checks if the certificate matches a specified IPv4 (ref:X509_check_ip). For example, connecting with 127.0.0.1 would required the following in the certificate:

    ```q
    X509v3 extensions:
    X509v3 Subject Alternative Name:
    IP Address:127.0.0.1
    ```

- .Q.atob companion for existing Q.btoa. Decodes base64 data. Accepts char or byte vector, returns byte vector. Throws domain error if data not correctly padded.

    ```q
    q)10h$.Q.atob "aGVsbG8="
    "hello"
    ```

- from the main thread (e.g. timer, console), hclose can close sockets used in other threads (e.g. when using multi-threaded input mode). Was possible prior to 4.1.

- TLS/SSL now supported for IPC when using inted/xinetd (or systemd when using a service with StandardInput=socket), ref: https://code.kx.com/q/kb/inetd/

- for binary HTTP responses .h.hn and .h.hy can now also accept byte vector (in addition to char vector) for data content e.g.

    ```q
    q).h.hn["200 OK";`jpg;read1`$":test.jpg"]
    ```

### Fixes and improvements

- When HTTP basic auth provided with non-padded base64 encoded data, default basic auth handling via .z.ac would truncate the data.

- e.g. (`$":http://127.0.0.1:5000")"GET / HTTP/1.1\r\nAuthorization: Basic QWxhZGRpbjpvcGVuIHNlc2FtZQ\r\n\r\n" (user:Aladdin,pass:"open sesam"). Now defaults to empty user/pass. Correct padded request would be

- (`$":http://127.0.0.1:5000")"GET / HTTP/1.1\r\nAuthorization: Basic QWxhZGRpbjpvcGVuIHNlc2FtZQ==\r\n\r\n" (user:`Aladdin,pass:"open sesame")

- When HTTP basic auth provided with base64 incorrectly encoded data with multple padding ('=') characters, the server could be corrupted or crash.

- When HTTP basic auth used, HTTP .z namespace callbacks would be called with corrupted data in the 'Authorization' header, when .z.ac set to return (4;""). This is the default action when .z.ac not defined. The

- base64 decoded username/password would appear in the HTTP data, with additional trailing characters. Now does not alter the HTTP payload provided. .z.pw is still called with decoded username/password.

- When running .Q.bv against a multi-segmented table, with a table missing from the same partition across segments, could result duplicate entries in .Q.vt. Now checks for duplicates for reduction in memory.

- pattern matching symbol vector literals could seg-fault

    ```q
    q){`a`b : x}`c`d
    profiler could sometimes seg-fault
    on mac os, when using threads the process could exit with an 'illegal instruction' error prior to the stack space protection q error 'stack
    q){v:(([]a:1 2);enlist(in;`a;(?;(`v;0);(`v;1);0b;(`v;2)));enlist[`a]!enlist `a);?[v 0;v 1;0b;v 2]}peach(::;::)
    Illegal instruction: 4
    now produces
    q){v:(([]a:1 2);enlist(in;`a;(?;(`v;0);(`v;1);0b;(`v;2)));enlist[`a]!enlist `a);?[v 0;v 1;0b;v 2]}peach(::;::)
    'stack
    ```

- Windows specific fix for mapped ragged splays which could leak memory. The following example situation was fixed

    ```q
    q)`:ragged/.d set`x`a;
    q)`:ragged/x set 1 2;
    q)`:ragged/a set 1993#(1 2;3 4);
    q)select from `:ragged/;.Q.w[]`mmap
    ```

- ([]a::e) now throws parse (previously was amend of global 'a' with implicit column name)

### New

- dictionary literal syntax extends table/keytable literals. same rules w.r.t implicit key names apply:

    ```q
    q)d:([k1:v1;k2:v2;..]);    k1:1;d:([k1;k2:2]);   d:([1;2]);d~([x:1;x1:2])
    similar to list literal syntax (;..), omission of values results in projection
    q)([k1:;k2:])[1;"a"] / ~ ([k1:1;k2:"a"]); compare: (;)[1;"a"] ~ (1;"a")
    pattern match: the left hand side of : can now be a pattern
    (a;b):(1;"ab")              / also: (a;b)::.. assign global; (a[0];b[1]):.. amend; (;b):.. empty pattern matches anything
    (1;b;c):(2;"ac";`x)           / throws 'match. on failure, the entire match fails and no assignments are made
    longstr:{$[10h=type x;"J"$x;'`type]} / a filter function can be used to check and transform values before assignment/return
    (a:longstr):"123"             / assigns a:longstr["123"]. rhs of (a:e) is any expression that evaluates (before match) to filter function
    (:longstr):"123"             / lhs pattern can be omitted if only the return value/check is of interest
    x:("12";5);x:(:longstr;:1+):x / x~12 6; equivalent to x:@[@[x;0;longstr];1;1+]; pattern return value used for complex amend
    ```
