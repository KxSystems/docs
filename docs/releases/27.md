# kdb+ 2.7 Release Notes

*This page details the latest features and improvements released to kdb+ 2.7.*

## 2013.06.20

### Fixes and improvements

- writing a list of primitives to a file could corrupt the heap, causing a crash at some point later, since v1.0

    ```q
    e.g. q)`:test set 3000000#(::);.Q.gc[]
    ```

- nested sync msgs could cause the socket to be closed erroneously, the remote throwing 'rcv: Resource temporarily unavailable.

    ```q
    e.g. q)h:hopen 55557;neg[h]@/:("0N!.z.w \"0N!{0}[]\"";"0N!.z.w \"0N!{1}[]\"")
    ```

- N.B. nested sync messaging is generally to be avoided; due to the nature of having to process incoming messages to reach a response,

    ```q
    the order of response messages may be incorrect.
    ```

### Fixes and improvements

- When slave threads are used, executing .Q.gc[] from the main thread did not execute gc in the slave threads;


## 2011.09.15

*(re-released as .Q.gc[] with cmd line param -g 1 was crashing)*

### New

- .Q.gc[] now coalesces unused memory before attempting to return memory to the OS.

    ```q
    Side effect is that .Q.gc[] can take longer to execute.
    .n.b. coalescing is always deferred, regardless of -g command line option for immediate/deferred garbage collection.
    ```

- .z.c now reports the number of cores that the kdb+ process is running on.

- \w now reports the physical memory of the machine, also .Q.w[]`mphy.

### Fixes and improvements

- `int$-0Wj was erroneously returning 0N (solaris on intel only)

- Multithreaded input mode would crash if handle 4 was closed, and views would stop working if handle 5 was closed.

    ```q
    Now they are blocked from being closed in this mode.
    ```

- To have .Q.chk consistent with meta, the latest partition is now used as the representative partition,

    ```q
    i.e. which schema is used for filling missing tables in an hdb.
    .e.g. q)ta:([]a:1 2);tb:([]b:1 2);`:hdbtest1/2011.01.01/t/ set ta;`:hdbtest1/2011.01.03/t/ set tb;
          q)\mkdir hdbtest1/2011.01.02
          q).Q.chk `:hdbtest1
    ```

- The heap tally reported by \w or .Q.w[] was incorrect for growing arrays on non-linux systems

    ```q
    e.g. q)a:((-16+`int$2 xexp 26)#0x0);a,:0x0;.Q.w[]`heap
    ```

- Now detects and exits if system essential functions are removed from .Q namespace

    ```q
    e.g. q).Q:{}
    ```

- Lower and upper now work with lists of char vectors

    ```q
    e.g. (upper;lower)@\:("aBC";"dEF")
    ```

- Enumerating an enumeration to a file wrote garbage into the file

    ```q
    e.g. q)`:foo?`bar?10000?`3;get`:foo
    ```

## 2011.04.30

### Fixes and improvements

- parsing of negative minute,second and time literals was erroneously extending to the next highest resolution time type.

    ```q

    ```

- select from a splayed table now maps files for the duration of the select, to reduce the number of times that a file is reopened/remapped.

    ```q
    this has a performance advantage for compressed files as the decompression is performed only once for the select. Select from partitioned tables benefits by extention, as these contain splayed tables.
    ```

- block \x if authentication in place (via cmd line -u/-U) or readonly (via cmd line -b)

- Properly detect and report exceeding the limit (4096) of concurrently open compressed files. File descriptor limits are

    ```q
    sockets - 1022
    uncompressed files - unlimited by kdb+ (2 billion)
    compressed files - 4096
    ```

- q.k - refined excel generation functions in .h namespace.

    ```q
    .h.ed / single table
    .h.edsn / dict of tables
    .h.es /sheet
    .h.eb /workbook
    ```

- q.k - added distinct as one of .Q.a0 i.e. an aggregator.

    ```q
    (the map-reduce does: (?:;,/ of the partition distincts))
    as select distinct .. by from a partitioned table was not executing distinct
    across the partitions. The behavior of distinct has been refined and behaves as follows
    - given select distinct a by b from t
      distinct can be used as an aggregator if there is a 'by'.
      unfortunately if there is no 'by'
      select distinct a,b from t
        has a different special meaning(meant to mimic sql92), namely
      distinct select a,b from t
    previously select distinct from t would work, but now throws a rank error
     similar to other unary ops. The fix is to use column names explicitly.
    ```

    ```q
    e.g. (x:-8!1 on sparc, then -9!x on intel) -9!0x000000000000000dfa00000001
    ```

- IPC deserialization of data compressed on non-native endian system was crashing.

    ```q
    i.e. sparc systems communicating with intel systems via ipc with messages large enough
    to activate compression (>2000 bytes) would cause crash during deserialization.
    ```

- zlib was being loaded even if decompression did not use it

## 2010.05.04

### Fixes and improvements

- \w 0 was not reporting correct usage of internalized symbols (since 2010.04.30)

- compressing a file was leaking memory

- file compression can now use the same compression algorithm as used in IPC, specify algorithm as 1,level is ignored, e.g

    ```q
    `:test set 10000000?10;-19!(`:test;`:ctest;17;1;0);get[`:test]~get`:ctest
    ```

- Moved zlib library dependency to run-time, i.e. if not using zlib compression it doesn't try to load zlib library.

## 2010.04.30

### New

- enhanced internalization of symbols to reduce latency spikes during insertion. This won't be noticeable to users who have a sensible schema,

    ```q
    but those who have millions of unique symbols in a process will find that the peak cost per insertion has been reduced.
    e.g. {s:.z.p;`$x;t,:.z.p-s;}each string til 20000000;max t
    ```

## 2010.04.28

### New

- file compression (linux,osx,solaris)

    ```q
    reads compressed and uncompressed files
    generate compressed files with -19!(`:infile;`:outfile;blockSize;algorithim;level)
    sets the logical block size to 2 xexp blockSize, the larger the blocksize the more efficient sequential access, but slower sparse/random access.
    currently algorithm must be 2 (gzip) and respective levels valid from 0 to 9.
    e.g. using gzip, level 6, 128kB block size
      `:test set 10000000?100;-19!(`:test;`:ctest;17;2;6);get[`:test]~get`:ctest
    append to compressed file not yet supported
    for compression, best performance will be when infile and outfile reside on different disks
    Note new library dependency - zlib is available from http://www.zlib.net or via your distributions package manager, e.g. yum install zlib
    ```
