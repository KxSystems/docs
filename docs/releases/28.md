# kdb+ 2.8 Release Notes

*This page details the latest features and improvements released to kdb+ 2.8.*

## 2015.05.28

### Fixes and improvements

- a SIGINT/'stop or wsfull during .Q.gc[] when using slave threads could cause a crash.

## 2014.11.26

### Fixes and improvements

- in,bin was erroneously sensitive to sort attr with compound types. e.g.

    ```q
    q)(10b;10b)~([] a:0 1; b:`)in/:(([] a:0 0; b:`);([] a:`s#0 0; b:`))
    ```

- find could crash for ()?int vector. e.g.

    ```q
    q)()?til 99
    ```

## 2014.05.03

### Fixes and improvements

- aggregating partial expressions would crash across partitioned databases. e.g.

    ```q
    q)`:p/0/t/`:p/1/t/ set\:([]a:til 10);system"l p";select sum(a+)from t
    ```

## 2014.03.19

### Fixes and improvements

- searching on compound key was erroneous since last release. e.g.

    ```q
    q)K:([a:1 2;b:`x`y]c:5 6);d:`a`b`c!(3;`c;4);K,:d;0N!K~([a:1 2 3;b:`x`y`c]c:5 6 4);
    ```

## 2014.03.16

### Fixes and improvements

- improve performance of searching on compound key e.g. x:([]a:..)cross([]b:..)

    ```q
    q)n:1000000;d:.z.d;t1:([]date:d;a:n?`4;b:n?1000f;c:n?1000000);m:100000;t2:([date:d;a:m?`4];b:m?1000f;d:m?1000)
    q)0N!system"ts t1 lj update date:`#date from t2";system"ts t1 lj update date:`s#date from t2"
    ```

## 2014.01.24

### Fixes and improvements

- match of mapped nested vectors was incorrect. e.g.

    ```q
    q)`:t/ set([]x:(1 2;3 4);y:(1 2;5 6));t:get`:t/;t[`x]~t`y
    ```

## 2013.11.20

### Fixes and improvements

- ij could perform very poorly when lhs had >99 rows, ignoring any attributes on 1st col of rhs

    ```q
    e.g. q)a:([]a:til 1;b:til 1);b:`a`b xkey update `g#a,c:i from([]a:til 1000)cross([]b:til 1000);(100#a)ij b
    ```

- -3!x now more efficient for stringify of enums

    ```q
    e.g. q)i:50000000?0Wi;e:`t!i;system"ts -3!e"
    ```

- allow "P"\$string .z.d so as to be consistent with "Z"\$string .z.d.

## 2013.09.05

### Fixes and improvements

- update with scalars for linked columns was not retaining type. Root cause was catenate.

    ```q
    e.g. q)t:([]1 2 3);([]x:1 2 3;p:`t!3#0N)~update p:`t!0N from t
         q)((enlist`x)!enlist 1 2 3),(enlist`p)!`t!enlist 0N
    ```

- assigning to .Q.s could cause a crash

    ```q
    e.g. q).Q.s:{}
    ```

## 2013.06.20

### Fixes and improvements

- writing a list of primitives to a file could corrupt the heap, causing a crash at some point later, since v1.0

    ```q
    e.g. q)`:test set 3000000#(::);.Q.gc[]
    ```

## 2013.06.14

### New

- heap accounting for reading compressed files is now based on what data is actually read rather than the full vector length,

    ```q
    and hence -w limits are less likely to be hit.
    ```

### Fixes and improvements

- using keyed tables as a step function was throwing 'nyi since 2013.06.06

    ```q
    e.g. q)(`s#([sym:1#`a;date:1#.z.d-1]symout:1#`a))flip(`a;100#.z.d);
    ```

## 2013.06.06

### Fixes and improvements

- w32 only - alloc > 4GB caused crash instead of reporting wsful.

    ```q
    e.g. q)1000000000#1
    ```

- nested sync msgs could cause the socket to be closed erroneously, the remote throwing 'rcv: Resource temporarily unavailable.

    ```q
    e.g. q)h:hopen 55557;neg[h]@/:("0N!.z.w \"0N!{0}[]\"";"0N!.z.w \"0N!{1}[]\"")
    ```

- N.B. nested sync messaging is generally to be avoided; due to the nature of having to process incoming messages to reach a response,

    ```q
    the order of response messages may be incorrect.
    ```

- multicolumn find (t1?t2) was slow for some scenarios if t1 had an attribute on the first column.

## 2013.03.05

### Fixes and improvements

- within inside select clause was not using comparison tolerance.

    ```q
    e.g. q)v:1+(til 3)*1e-16;0N!3=count select from ([]v) where v within v 2 2;
    ```

- garbage collect could result in seg fault instead of printing wsfull.

    ```q
    e.g. q)((1+)\)0 / iterate forever on 32bit kdb+
    ```

## 2013.01.04

### Fixes and improvements

- comparison tolerance was too tolerant on 0=1e-256 (0 should only be equal to 0).

## 2012.12.22

### Fixes and improvements

    ```q
    e.g. q)t:([]a:2 3;b:("as";"qwe"));t,:([]a:3 4);([]a:2 3 3 4;b:("as";"qwe";"";""))~t
    ```

## 2012.12.20

### Fixes and improvements

- \` vs \`sym?\`a.b\`c was crashing, instead of throwing 'type.

## 2012.12.05

### New

## 2012.09.06

### Fixes and improvements

- select with a "date.[month|year] in .." was not matching correctly if rhs was not sorted and unique.

    ```q
    e.g. q)select from([]t:enlist 2001.01.01)where t.month in 2001.02 2001.01m
    ```

- setting a \`p attribute on a vector which already had a \`u attribute was crashing (immediately or later), since v1.0

    ```q
    e.g. group `p#`u#-20?20;
    ```

## 2012.09.02

### Fixes and improvements

- added rank check to lj to catch error case which was causing a crash

    ```q
    e.g. q)([]a:1 2;d:1 2),\:([a:(1 2;1 2)]f:3 4)
    ```

- q.k - .Q.bv kept files in the last partition mapped if they were empty.

## 2012.08.02

### Fixes and improvements

- built-in logging via -l could log bad data if incoming ipc msg was compressed.

### Fixes and improvements

### Fixes and improvements

- block x!y if either one is splayed, as {x!x}flip\`a\`b!\`c was crashing

- passing bad args to file compression could crash, e.g.


## 2011.10.06

### New

- q.k - set now supports (\`:file|\`:splay/;blockSize;algo;zipLevel) for streaming compression.

- append to (kdb+ built-in compression) compressed files

    ```q
    e.g. q)(`:zippedTest;17;2;9) set 100000?10;`:zippedTest upsert 100000?10;-21!`:zippedTest
    ```

- 'compress new files' mode - active if .z.zd (zip defaults) present and valid.

    ```q
    .z.zd can be set to an int vector of (blockSize;algo;zipLevel) to apply to all new files which do not have a file extension.
    -19!x and (`:file;size;algo;level) set x override .z.zd for that file/splay
    ```

### NUC (Not Upwardly Compatible)

!!! note "Not backward compatible. Changes existing behavior."

- -19!(\`:infile;\`:outfile;blockSize;algo;zipLevel) now returns outfile. Previously it returned achieved compression. Use -21! to obtain meta info.

- -19!x will not revoke compression if compressed size > original size; this is to avoid to and fro with append to compressed files.

- changed parser to properly allow (/) etc, supporting each right as standalone,

    ```q
    e.g. q)type(/:)
    [space]/ is a comment but ;/ (/ [/ {/ are not. No one should be using these as comments.
    Please do a grep on your code to see if you ever used these.
    ```

- On unix, system redirects output for capture via /tmp/XXXXXX

    ```q
    e.g. q)system"ls"
    ```

- File compression - don't try to compress a # file for nested data, as it will be compressed

    ```q
    as part of compressing its partner file. e.g.
    q)`:a set 1000#enlist asc 1000?10;-19!(`:a;`:za;17;2;9);0N!get[`:a]~get`:za;
    ```

### Fixes and improvements

- improved mmu performance (osx,linux)

    ```q
    e.g. q)\t x$flip x:380 70000#1.0
    ```

- osx build now supports multithreaded modes
