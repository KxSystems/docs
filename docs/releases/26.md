# kdb+ 2.6 Release Notes

*This page details the latest features and improvements released to kdb+ 2.6.*

## 2012.08.03

### Fixes and improvements

- built-in logging via -l could log bad data if incoming ipc msg was compressed.

## 2012.05.30

### Fixes and improvements

- patch for v2.6 to use ipc with v3.0, to allow it to send timestamp/timespan.

## 2011.07.21

### Fixes and improvements

- files containing a single vector with a `u attribute were erronesouly being read in full rather than mapped, since 2010.12.03.

    ```q
    e.g. q)get `:testu set `u#til 1000
    ```

## 2011.04.11

### Fixes and improvements

- deltas(1 2 3;4 5 6) was throwing 'length

## 2011.03.26

### Fixes and improvements

- ipc compression could potentially cause heap corruption in extremely rare cases, since 2.6 2010.02.02

- Since 2.6 2010.09.08, 'accp error was losing the context of the error and hence showing wrong text. The text is OS specific.

    ```q
    e.g. was "Bad file Descriptor" instead of "Too many open files".
    ```

## 2011.02.04

### Fixes and improvements

- potentially, in extremely obscure cases, a sym compare might have matched incorrectly. This affects finding unique rows

    ```q
    in tables where at least one column is a sym.
    ```

- allow upsert of empties

    ```q
    e.g.([x:1 2]y:3 4)upsert([]x:`int$())
    ```

- 0!x was not decrementing ref count of x in the event of a type error

    ```q
    e.g.0!()
    ```

## 2011.01.20

### Fixes and improvements

- calling code in dynamically loaded libraries on linux could crash randomly, since v1.0

- select from symbol could result in an infinite recursive loop and consequent crash due to stack exhaustion, since 2.6 2009.08.20.

- Now blocked by allowing just one level of indirection, as originally intended, throwing 'type if further levels are detected.

    ```q
    e.g.
     t:`t;select from t
    ```

- was crashing if the sort column name was missing from select[m n;&lt;colname] from ...

    ```q
    e.g. select[4 2;<] from([]a:til 10)
    ```

## 2010.12.17

### Fixes and improvements

- appending an empty list to a nested type was throwing 'type since 2.6 2010.06.17

    ```q
    e.g. `:test set("hello";"world");`:test upsert()
    ```

## 2010.12.03

### Fixes and improvements

- loading a file created with v2.5 which contained only `g#0#0h caused a crash.

    ```q
    n.b. this particular file created with with versions>2.5 is not compatible with versions<=2.5.
    ```

- (internal) kdb+ could crash if stringify was not already initialized when an error was encountered, since v1.0.

- Querying an unknown file based table could caush a crash

    ```q
    e.g. select from (flip enlist[`x]!`:t/) where i<1
    ```

- wj wasn't giving consistent results for joins using a single column

    ```q
    e.g.
     wj[-2 1+\:t.time;`time;t;(q;(::;`ask);(::;`bid);(::;`time))]
     wj[-2 1+\:t.time;enlist `time;t;(q;(::;`ask);(::;`bid);(::;`time))]
     wj[-2 1+\:t.time;`sym`time;t;(q;(::;`ask);(::;`bid);(::;`time))]
      given
     q:([]sym:9#`ibm; time: 10:01:01 + til 9; ask: 101 + til 9; bid:98 + til 9);
     t:([]sym:3#`ibm; time: 10:01:01 10:01:04 10:01:08; price: 100 101 105);
     f:`sym`time;w:-2 1+\:t.time;
    ```

- cor, cov, dev and var were not working correctly on selects from partitions when no constraints were used, since 2.6 2009.10.15.

    ```q
    e.g.
     `:db/test/2010.09.20/t/ set([]p:1 1 1 2 2;r:1 2 3 4 5);
     `:db/test/2010.09.21/t/ set([]p:10 11;r:2 3);
     \l db/test
     {(x cor y)~z}[(select r from t)`r;(select p from t)`p;first (select r cor p from t)`p]
    ```

## 2010.09.08

### Fixes and improvements

- file/socket descriptors were being inherited by child processes (e.g. via system"...") - present since initial version of kdb+.

    ```q
    This meant file descriptors in use by a terminated parent process at the time of creating the child process would remain
    in existence until the child process terminated.
    ```

### Fixes and improvements

### Fixes and improvements


### Fixes and improvements

- msum extended to work with dictionaries, e.g. 3 msum til[6]!1 2 3 5 7 11

- ?[10b;([]1 2);([]3 4)] throws 'nyi not 'type

- e.g. hopen[`:127.0.0.1:9999] 'conn: Connection refused

- record#keyedtable was crashing. e.g. r:(flip(enlist\`id)!enlist())!();r(enlist \`id)#r

## 2010.05.17

### Fixes and improvements

- loading a `s#enum without the enum target was throwing g0 error

- -17!x where x was non-native endian `p#sym enum was crashing

- min on a sorted list was not ignoring nulls, e.g. min asc 0n 1

## 2010.05.10

### Fixes and improvements

- upsert on a keyed table with dicts as values was failing if a new key element was added (since 2009.08.07 release)

- e.g. t:([a:\`a\`b]v:(\`n\`m!(\`a;1 2 3);\`a\`b\`c!(1;2;\`a)));r:([a:enlist\`x]v:enlist enlist[\`a]!enlist 1 2);t,:r

## 2010.05.09

### Fixes and improvements

- -9!x was failing with 'length error if x was serialised on a non-native endian system.

    ```q
    e.g. (x:-8!1 on sparc, then -9!x on intel) -9!0x000000000000000dfa00000001
    ```

- IPC deserialization of data compressed on non-native endian system was crashing.

    ```q
    i.e. sparc systems communicating with intel systems via ipc with messages large enough
    to activate compression (>2000 bytes) would cause crash during deserialization.
    ```

### Fixes and improvements

## 2010.04.22

### Fixes and improvements

- q.k - for partitioned tables, select count i .. from t where ... was returning different types (int,long) depending on whether there were more constraints than just date, e.g. ... where date=2010.04.21,sym in syms. Fixed to always returns a long (for querying partitioned tables), and can be explicitly cast back to an int if necessary, e.g. select `int$count i from t ...

### Fixes and improvements

### Fixes and improvements

### Fixes and improvements

## 2010.04.07

### Fixes and improvements

- q.k - aj0 did not take the rest of the columns from the left table, e.g. aj[`t;([]t:1 3;a:01b);([]t:til 4;b:"abcd")]

- q.k - wj match on 1 or 2(with \`p#sym or \`g#sym) fields only. Previously was 2 fields only.

- q.k - literals for type comparisons changed to explicit shorts (avoids cost of coersion),

    ```q
    e.g.
    q)\t do[100000;99=99h]
    35
    q)\t do[100000;99h=99h]
    16
    ```

- select distinct b by a from t was sensitive to extra whitespace between "distinct b",

    ```q
    e.g.
    q)(select distinct  b by a from ([] a:`z`z;b:1 1))~select distinct b by a from ([] a:`z`z;b:1 1)
    0b
    also
    q)(select distinct[b] by a from ([] a:`z`z;b:1 1))~select distinct b by a from ([] a:`z`z;b:1 1)
    0b
    select distinct expression by ..  is allowed, otherwise select distinct ..  must have no 'by' (just like sql92 has no group by)
    and means distinct select ..,
    e.g.
    q)select distinct by b from ([] a:`z`z;b:1 1)
    'distinct by
    q)(distinct select from ([] a:`z`z;b:1 1))~select distinct from ([] a:`z`z;b:1 1)
    1b
    ```

## 2010.03.13

*(entry updated 2010.04.22)*

### Fixes and improvements

- update with a new length was failing, since 2009.11.10 release, e.g. update a:1 2 3 from ([]a:1 2)

- a side effect is that update is more strict with lengths; the new length must be 1 or the length of the existing column.

    ```q
    e.g. update b:1 2 3 from([]a:1 2) now fails, correct code would be update b:count[i]#1 2 3 from([]a:1 2)
    e.g. update b:1 2 from([]a:1 2 3) now fails, correct code would be update b:count[i]#1 2 from([]a:1 2 3)
    ```
